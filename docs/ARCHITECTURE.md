# Как устроен VPN Lens

[English](ARCHITECTURE.en.md)

## Слои

```
crates/core                  Rust: сокеты по процессам, интерфейсы, прокси, DNS,
                             проверочные запросы, вердикты и тексты проверок
crates/cli                   консольная утилита vpnlens
crates/uniffi-bindgen        генератор Swift-привязок
macos/Sources/VPNLensLogic   логика защиты и kill switch без AppKit, с тестами
macos/Sources/VPNLens        приложение: меню, окно, уведомления, защита
```

Логика написана на Rust один раз, интерфейс на каждой ОС свой. Ядро ничего не хранит и
ничего не решает за интерфейс: оно снимает сокеты, делает проверочные запросы и
возвращает типизированные модели через [UniFFI](https://mozilla.github.io/uniffi-rs/).

Ядро работает без root и особых разрешений:

- сокеты процессов - `netstat2` (`proc_pidfdinfo`), дерево процессов - `sysinfo`;
- прокси, DNS, типы интерфейсов и подпись сети - SystemConfiguration;
- запросы через физический интерфейс - `socket2` с `IP_BOUND_IF` и `rustls`;
- STUN - свой маленький клиент на UDP.

## Как решается, что трафик идёт мимо VPN

Соединение через Wi-Fi ещё ничего не доказывает: многие VPN-клиенты забирают в туннель
и такие сокеты. Поэтому VPN Lens отправляет проверочный запрос, привязанный к
физическому интерфейсу (`IP_BOUND_IF`), и смотрит, с каким адресом он вышел.

| Конфигурация | Запрос через Wi-Fi вышел с | Программа с соединениями через Wi-Fi |
|---|---|---|
| VPN не включён | адресом провайдера | «VPN выключен» |
| Полный туннель с запретом обхода | адресом VPN | «Через VPN» |
| Раздельный туннель | адресом провайдера | «Мимо VPN» |
| Только системный прокси, без туннеля | адресом провайдера | «Мимо VPN», если не использует прокси |
| Запрос не дошёл | - | «Не проверено», а не «всё хорошо» |

Красным помечается только то, что подтвердил замер. Служебные адреса туннеля
(198.18.0.0/15), локальный прокси VPN-клиента и соединения самого клиента утечкой не
считаются. Вердикты - чистые функции от замеров в
[`crates/core/src/report.rs`](../crates/core/src/report.rs), и каждая строка таблицы покрыта
тестом.

Остальные проверки:

- **UDP:** STUN-запрос, как у WebRTC в браузере. Частая утечка у VPN, работающих только как прокси.
- **IPv6:** есть ли у физического интерфейса публичный IPv6 и выпускает ли его VPN.
- **DNS:** кому система отправляет запросы. Кто их в итоге получает, показывает внешний
  DNS-тест через bash.ws: VPN Lens открывает уникальные поддомены и спрашивает сервис,
  какие резолверы за ними пришли.
- **Адрес по сайтам:** VPN-клиенты с правилами по доменам пускают часть сайтов другим
  путём. Если проверочные сайты видят разные адреса, показываются все.
- **VPN-клиент упал:** системный прокси указан, но на его порту никто не слушает.

Адрес провайдера запоминается для каждой сети отдельно, по подписи роутера, которую
ведёт macOS (`NetworkSignature`). Хранится хеш, а не MAC-адрес.

## Защита приложений

Событие «туннель пропал» приходит от `NWPathMonitor`, плюс запасная проверка раз в
5 секунд, пока список защищённых программ не пуст. Проверка - список интерфейсов и
пробное подключение к локальному прокси, около 0,7 мс.

Helper-процессы защищённых программ VPN Lens знает заранее (обновляет список раз в
30 секунд), поэтому известные процессы замораживает сразу, а новые, появившиеся после
обновления списка, находит отдельной проверкой и останавливает следом. В тестовом
сценарии, где процесс открывал соединения пять раз в секунду, заморозка известного дерева
заняла 26 мкс, и за три секунды заморозки не прошло ни одного соединения. Это замер
одного сценария, а не гарантия: между обрывом и событием от системы тоже проходит время. Защита включается только после того, как VPN хоть раз
был виден, иначе она заморозила бы программы у человека без VPN. Если VPN Lens закрыть
или он упадёт, замороженные программы отпускаются, при падении - на следующем запуске,
с проверкой времени запуска процесса, чтобы не тронуть чужой процесс с тем же pid.

Настоящая блокировка на уровне сети возможна через системное расширение Network
Extension (`NEFilterDataProvider`, как у LuLu), но для него нужен платный аккаунт Apple
Developer, подпись Developer ID и нотаризация.

Переходы состояний защиты и итог проверки kill switch вынесены в модуль `VPNLensLogic`
без AppKit и проверяются Swift-тестами.

## Интерфейс macOS

Меню - SwiftUI внутри настоящего `NSMenu`. Так система считает панель меню: в
полноэкранном режиме строка меню не прячется, пока панель открыта, а закрывается она
сама по клику мимо, Esc, Cmd+Tab и смене рабочего стола. До этого были `MenuBarExtra`
(верх панели уезжал под строку меню при смене высоты) и своё окно `NSPanel` (в
полноэкранном режиме строка меню пряталась сразу после клика). Высоту содержимого
меряет сам SwiftUI (`onGeometryChange`): пока меню открыто, `NSHostingController` о новом
размере не сообщает.

Окно - `NavigationSplitView` в обычном `NSWindow`. Пока оно открыто, у приложения есть
иконка в Dock, после закрытия VPN Lens снова живёт только в строке меню.

## Языки

Интерфейс на русском и английском. По умолчанию - как в системе, в настройках можно
выбрать язык отдельно (как в «Системные настройки → Язык и регион → Приложения»).
Русский - язык разработки и запасной для остальных языков. Тексты проверок ядро
собирает на нужном языке, строки интерфейса переводятся через `Localizable.strings`.
Скрипт `scripts/check-localization.sh` берёт ключи у самого компилятора Swift и
проверяет, что у каждой строки есть перевод.

## Сборка и отладка

Нужны Xcode 16 и Rust. Для сборки под Intel и Apple Silicon сразу нужен
[rustup](https://rustup.rs): Rust из Homebrew умеет только архитектуру своего Mac.

```sh
scripts/build-app.sh --run          # собрать "build/VPN Lens.app" и запустить
scripts/build-app.sh --universal    # Apple Silicon + Intel
scripts/build-app.sh --zip          # ещё и архив с SHA-256 для релиза
```

Консольная утилита на том же ядре (по-английски с `LANG=en_US.UTF-8`):

```sh
cargo run -p vpnlens-cli              # полная проверка
cargo run -p vpnlens-cli -- --offline # без запросов в интернет
cargo run -p vpnlens-cli -- app chrome
cargo run -p vpnlens-cli -- report    # отчёт текстом
cargo run -p vpnlens-cli -- dns       # внешний DNS-тест
```

Что проверяет CI:

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
swift test --package-path macos
scripts/check-localization.sh
```

Флаги приложения для отладки и скриншотов:

- `--open` - открыть меню сразу после запуска;
- `--window apps` - открыть окно на разделе (`overview`, `apps`, `protection`, `checks`,
  `history`, `network`, `settings`);
- `--snapshot menu.png --app Safari` - нарисовать меню в файл;
- `--demo` - подменить настоящие адреса адресами для документации (RFC 5737), так сняты
  все скриншоты в README;
- `--tour` - вместе с `--window` по очереди показать разделы окна, для GIF;
- `--promo apps|drop` - заранее заданный список программ вместо настоящих соединений и
  сработавшая защита (`drop`), для ролика. Настоящий список защиты и история не меняются.

Тег `vX.Y.Z` собирает универсальный архив и создаёт черновик релиза с описанием из
CHANGELOG. После публикации релиза `scripts/update-cask.sh X.Y.Z` обновляет cask для
Homebrew.

Под Windows и Linux ядро собирается, но прокси там берётся только из переменных окружения,
а оболочки интерфейса нет.
